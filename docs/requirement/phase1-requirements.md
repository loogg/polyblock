# PolyBlock Phase 1 需求与范围说明

## 1. 产品定位与命名
- **产品名称**：**PolyBlock**（多语言积木编程工作台）
- **核心目标**：以搭积木的方式可视化编排逻辑，单向实时生成多种目标脚本代码（Phase 1 先行支持 **Lua 5.4** 与 **Python 3**），支持浏览器内零后端沙箱试跑看打印日志，并支持一键导出脚本供外部系统运行，可直接托管于 GitHub Pages。

## 2. 已确认的核心决策
1. **底层积木引擎**：采用 **Google Blockly（v13）** 作为核心底座，通过继承 `zelos` 渲染器与自定义主题复刻 **MicroBlocks** 的紧凑高颜值风格。
2. **界面布局**：采用 **方案一（MicroBlocks 紧凑工作台）**——左侧 54px 深色主导航轨承接多页面扩展 + 双栏带搜索积木箱 + 点阵主画布 + 可各自折叠的右侧代码预览与底部打印日志台（原型参考：[layout-showcase.html](../ui-prototype/layout-showcase.html)）。
3. **脚本与执行模式**：
   - **单向生成**：积木 → Lua / Python 只读预览与文件导出。
   - **双场景兼顾（C）**：支持浏览器纯前端 WASM Worker 沙箱本地试跑调试，同时支持一键导出标准 `.lua` / `.py` 文件。
   - **可插拔 Runner 架构**：解耦前端编排与底层执行目标，Phase 1 内置浏览器 Lua / Python WASM 运行器，后续接入网络设备（WS/HTTP）、本地桥接或桌面壳无需改动前端 UI。
4. **部署形态**：纯静态 Web 构建，兼容 **GitHub Pages**（相对资源路径、Hash 路由、不依赖 `SharedArrayBuffer` / COOP·COEP 响应头）。

## 3. Phase 1 范围取舍

| 能力模块 | 支持任务 | Phase 1 处理 | 理由 |
|---|---|---|---|
| 多页面侧边栏导航 | 切换编程、项目、设备、扩展、设置 | **完整纳入**（设备/扩展先提供架构预览与扩展占位） | 满足后续设备下载与扩展包平滑扩页需求 |
| MicroBlocks 风格积木画布 | 拖拽、拼接、缩放、撤销重做、分类与关键词搜索 | **完整纳入** | 核心交互与第一视觉体验 |
| 基础积木 + 打印日志模块 | 事件、打印/分级日志、控制、变量、运算、逻辑、文本、列表、函数 | **完整纳入** | 覆盖通用脚本编排与日志调试刚需 |
| Lua 5.4 / Python 3 双后端 | 一键切换语言、实时代码高亮、积木↔代码行双向定位、导出 | **完整纳入** | 核心多后端架构验证 |
| 纯前端 WASM 沙箱运行 | Worker 中真实运行 Lua / Python、实时日志流、超时与强杀 | **完整纳入** | 零后端即可完整试跑并验证导出脚本正确性 |
| 项目存取与示例模板 | LocalStorage 自动保存、`.polyblock.json` 导入导出、内置示例 | **完整纳入** | 形成完整创作与分享闭环 |
| 网络/串口硬件下载通信 | WebSocket/HTTP/本地桥接下发设备 | **暂缓至 Phase 2**（保留 `ScriptRunner` 接口与页面占位） | 用户明确一期先不接入网络和设备通信 |
| 文本代码反向生成积木 | 手改代码自动同步画布 | **排除** | 用户明确采用单向模式 |
